Feature · Adversarial verification

Guesses are cheap. Argus tries to kill them.

reasoning trace (illustrative)
Theia   claim #1  "database is overloaded"
Themis  REFUTED   db.log:212 cpu=31% p95=18ms, normalAthena  re-plan → look at changes before 14:07
Chronos suspect 6c95fcb "return early on declined"
Theia   claim #2  "early return skips pool.release()"
Themis  SUPPORTED checkout.py:48 + deploy.log:9Hephaestus patch: release in finally (4 lines)
Talos   before: pool exhausted  after: healthy
  • A separate fact-checker with its own context attacks each claim, and must cite evidence to rule.
  • Every quote is checked by code against the real file and line. Made-up evidence never gets in.
  • Symptoms aren't enough. A cause must be backed by the code or the change itself.
  • The plan adapts. When a guess dies, the Commander re-plans. After 3 failed attempts, a person takes over.

Judging · Governance & responsibility
Governance by design

The AI proposes. Policy and people decide.

Human approval gate

Approvers set per severity. Optional two-person rule with a team lead for sev1/2. The reporter can't approve their own serious fix. Declines need a reason.

Rules in one file

policy.yaml: allowed fix types, protected paths (secrets, migrations, CI), max 80 lines per fix. Break a rule → sent back to the fixer.

Hard stops

AI budget per incident (₹25): over it, Argus stops and hands over. 3-attempt limit. Approval SLA escalates to the lead after 10 min.

Tamper-evident audit log

Every event is hash-chained to the one before. Edit, delete or reorder anything and /audit/verify shows where.

Every decision explained

Each approval, block and stop records the rule that applied and the policy file's fingerprint.

Role-based access

Testers, developers and leads, checked server-side on every write. AI usage, tokens and energy shown on every ticket.
